# 外部审查修复记录（v1.0.2）

基于针对 af5464b 的审核与测试报告修复；模拟测试通过不等于真实群验收完成。

| 报告问题 | 本轮处理 |
| --- | --- |
| 同一次模型 OCR 被当独立证据 | 只看原消息的本地规则；模型 OCR 仅展示/管理员确认后学习，纯图人工复核 |
| 问号/反诈词后缀绕过规则 | 明确推广与联系引流组合不整体豁免；正常问题和开头反诈提醒保持保守 |
| 低权限管理员借 Bot 封禁 | 指令、群/频道按钮、案件面板以及 execute 校验源群限制成员权限；身份豁免不变 |
| 白名单/开关权限过宽 | 主人或本群群主可修改；其他管理员可查看 |
| 封禁失败/超时卡死 | 提供人工核对重试入口，先查询永久封禁状态；不自动重放，不重复删帖/归档 |
| 摘录伪造结构字段 | 摘录每行加标记；姓名/理由等压为单行并去方向控制符；保留原始证据快照 |
| AI 重定向转发密钥 | 阻止所有重定向；HTTP 仅字面回环地址 |
| restricted 非成员投票 | 必须 is_member=true |
| SQLite replace 空操作 | 改为真实换行参数，补回归测试 |
| 自删证据误标无法核实删除者 | 使用已持久化删除结果区别已确认自删与删除者未知 |
| 同人其他待复核案件误导 | 已确认封禁后关闭其他未结复核，撤销按钮 |
| 每切换设置整库备份 | 改为同事务100条策略历史，不复制消息正文 |
| systemd 权限加固 | 清空能力集，禁止命名空间 |
| 无 git 导出包无法脱敏检查 | 允许扫描导出目录所有交付文件 |

新增21项针对性回归，全套259项在 Python 3.12 以 -W error 通过；compileall 通过。GitHub CI 的 Python 3.11/3.13 结果需另行确认。

本轮未替换 Telegram 同步主循环并发架构，单次调用最多8秒仍可能积压；也未进行真实成员的禁言/恢复/驳回/永久封禁验收。API 无法归因完全相同的外部禁言或封禁动作；恢复时确认的是 Telegram 当前永久封禁状态，不声称证明封禁由本 Bot 造成。AI 图像依旧有误识别风险，管理员需要看证据。

部署前应备份源码、配置与 SQLite，核验运行源码未被其他任务修改、验证上游地址可通过新校验。生产凭证与消息数据库不进入代码仓库或审核包。
