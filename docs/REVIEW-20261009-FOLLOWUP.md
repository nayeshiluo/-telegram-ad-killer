# v1.0.3 二次复审修复

v1.0.2 的反诈后缀修复确实只覆盖了部分组合。本轮修正，不将前次259项通过作为这些新场景已经安全的证据。

| 复审发现 | 修复和证据 |
| --- | --- |
| 免费领取虚拟卡 t.me/somebot?start=x 后加反诈宣传变 clean | 明确机器人引流独立判断，不继承整条消息的 caution 豁免；链接、提及、inline、隐藏链接均回归 |
| 加微信 abc123 稳赚不赔，兼职日结漏判 | 补加微信/添加微信/加薇信联系方式，组合收益/业务信号，问号及反诈后缀均回归 |
| 提醒前缀可伪造 | 强推销/联系或机器人邀请不再由前缀直接豁免；带广告引用的真实提醒交 AI/人工理解上下文；单纯反诈提醒仍保守 |
| 图片 opener 跟随跳转 | 与模型使用同一禁止重定向 opener，忽略 API 自带 opener；补真实重定向处理链模拟、正常PNG及不支持格式测试 |

新增11项测试，全套270项 Python3.12 -W error 通过。图片重定向测试模拟 HTTPS 响应并经过 urllib 的实际重定向处理链，不请求真实 Telegram 文件；成功格式测试使用合成 PNG 字节。不是 Telegram 完整图片端到端验收。

权限即时校验、单线程同步 Telegram 调用及8秒超时仍有吞吐风险，未以权限缓存掩盖这一限制。真实禁言、恢复、驳回和封禁仍需测试账号验收。关键词及 AI 无法保证对所有广告变体零误判/零漏判；反诈引用有强引流证据时可能进入疑似，AI失败/关闭时仅人工卡片，不据此直接删帖禁言。
