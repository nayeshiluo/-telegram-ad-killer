# v1.0.4 响应速度改进

## 已观察的数据

更新前从运行日志最后3000行提取306次消息处理及35次按钮回调：消息中位数6ms、最大528ms；回调中位数1606ms、最大9443ms。这是处理耗时，不包含用户点击到服务器收到更新的时间，也不是全量历史统计。进程内存约19MiB。

## 修改

- 同一命令授权流程只读取一次当前操作者身份；不跨命令缓存权限。破坏性操作内部仍实时核验权限。
- 隔离流程移除连续重复的目标身份查询：总getChatMember从7次减到5次，目标身份检查仍3次；禁言后删除前继续重新检查，避免中途升为管理员后删帖。
- 每轮先处理Telegram更新，再处理最多1个AI结果；原来在拉取更新前可能处理20个AI结果。SQLite和处罚仍在主线程串行执行。AI积压时每个结果需等待轮询，不承诺所有场景吞吐增加。

## 验证及限制

新增6项测试覆盖查询数量、准备期间和禁言期间身份变更、跨命令撤权、缺少禁言权限、实际主循环的AI积压调度及offset提交。

离线模拟每次权限查询20ms：旧流程7次约143ms，新流程5次约102ms。此结果仅验证网络往返减少，不代表生产响应提升比例。

Telegram网络、同步API调用（最长8秒）、单个案件归档和定时清理仍可能阻塞主循环。本版是局部改进，不宣称消除全部延迟。实际禁言、恢复及永久封禁验收仍需专用测试账号；模拟测试不能替代真实群验收。
