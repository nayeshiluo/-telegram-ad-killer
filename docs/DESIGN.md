# 广告杀手 v1.0.0：流程、规则与执行方案

## 目标与范围

独立 Telegram Bot，Python 标准库、SQLite、systemd；不合并群霸，不依赖人型账号。规则优先，AI辅助；管理员决定的广告才进入学习库。每个群单独授权、配置和处罚，全局白名单仅机器人主人维护。

本版借鉴公共机器人的公开功能及用户提供的管理记录截图，没有拿到或复制这些机器人的内部模型、源码或完整关键词库。参考：

- https://t.me/GuangGaoShaShouBot ：中文广告、简化操作、误封处理入口。
- https://t.me/zftestbot ：转发、引用、名片、定位等行为识别。
- https://grouphelp.me/en ：反垃圾、重复推广、独立功能设置。
- https://t.me/AutoAdBlockerBot ：简介提供日志频道，本轮未能读取其案例。
- 用户截图：记录编号、身份、北京时间、判定来源、原文摘录、处理按钮。

## 一条消息的完整流程

1. 只接受配置中的授权群；新消息与编辑消息均可检测，管理命令只在新消息执行。
2. 先处理合法管理指令。机器人主人、群主、群管理员、本群/全局白名单豁免自动处罚。身份查询失败时不处罚。频道身份或匿名管理发言不映射为某个成员ID。
3. 在review模式查询本群有效封禁ID、管理员确认的独特广告原文。命中时重新核查身份与权限，先归档再执行删除/封禁；不依靠AI决定已确认记录的重复处罚。
4. 本地规则解析文字、说明、显式与隐藏链接、内联机器人信息、外部转发/引用、名片和定位。正常讨论、提问、反诈语境降低弱规则判定。
5. 已配置黑名单域名属于明确规则；其他业务、推销、引流组合为疑似。单独出现VPS、GPT、USDT、链接、@机器人、图片、转发、定位均不是封禁理由。
6. 本群120秒内至少3条不同消息出现相同推广文字与链接，增加“重复推广”证据。只统计原本已有疑似信号的消息；不把正常聊天重复当广告，不因重复单独触发超时封禁。
7. 根据本群开关提交AI文字/照片复核。AI异步执行，不阻塞消息接收；只输出spam/normal/uncertain及理由。AI不能操作Telegram或修改学习库。
8. review模式下：AI判spam且本地规则或可读照片广告文字同时命中，创建180秒倒计时；仅AI怀疑、仅重复信号、无AI的疑似规则只创建人工复核，截止时间为0。
9. 复核结束按下文执行。observe模式只记录检测；管理员主动/adreview可模拟复核。自动检测不会在observe模式自动创建大量卡片。

## 处罚模式

| 模式 | 自动行为 |
| --- | --- |
| observe | 只检测和记录；复核测试按钮只模拟，不删帖、不封禁 |
| review | 已确认ID/独特原文重复可直接处罚；普通疑似按三分钟复核或人工复核 |
| delete | 仅明确域名黑名单消息自动删除，归档，不封禁 |
| ban | 仅明确域名黑名单消息自动删除并封禁，归档 |

升级部署保留现有模式，不自动开启真实处罚。主人在群执行`/admode review CONFIRM`才开启review；首次使用建议先在测试群验证。

## 三分钟复核与三个按钮

- 群友驳回：本群3个不同成员，各一票。被审查的成员不能给自己的真实案件投票。重复点击不增加票数。
- 管理驳回：本群群主/管理员或机器人主人一次即可取消处罚。
- 核实封禁：本群群主/管理员或主人一次即可执行。执行前再次查询目标身份、白名单及机器人权限。
- 180秒到期且没有驳回成功：只对证据足够的真实案件封禁；仅人工案件不会超时处罚。
- 离线超过截止时间120秒的积压案件转人工复核，恢复时不批量封禁。
- 消息被编辑时，旧待复核案件取消，旧AI结果不处罚；不自动把同编号旧案件复活，管理员可主动回复编辑后原文确认。
- 案件终结、模式变化、白名单变更均阻止重复处罚。按钮必须来自原复核消息，转发的卡片无效。

本版保留“复核完成后删帖和封禁”。截图的“首次立即删帖并禁言”暂不实现：需要保存原ChatPermissions、恢复原有禁言和处理离线恢复，不能简单解禁全部权限。若以后增加，作为独立可选策略，不改变默认三分钟流程。

## 执行、失败和记录

真实处罚依次为：身份核查→源群/归档频道权限核查→复制原始证据→发送归档卡片→再次核查目标→删除→再次核查目标→封禁→事务保存ID/学习。

- 归档失败，不删除或封禁；删除失败，不继续封禁。
- 超时、网络错误不代表动作必然没执行；保留“失败或不确定”状态，禁止盲目重试。
- 重启中断动作进入待人工核查状态，不自动重放。
- 删除、封禁完整成功后，才把ID记为有效封禁。记录范围为原群，跨群不能凭一个群的管理员判定自动处罚。
- 自动超时、AI自己和公共样品不生成已确认学习样本。
- 原记录可检索，失败可追踪，不把模型自述99%显示为真实概率。

## 主动封禁与学习

管理员在本群回复广告：`/adkill CONFIRM`。observe模式也会真实执行，必须有CONFIRM。

成功后保存本群用户ID与独特广告文字。至少20个归一化字符才进入案件学习；最多保留每群1000条案件样本。照片只有审核中实际读取、且与同一消息内容摘要对应的OCR文字才可学习；不根据图片猜测未读到的文字。

- 完整、独特原文重复命中可按管理员已确认样本处理。
- 相似文本只标疑似，不能凭相似度直接封禁。
- 主人`/adlearn`只学习、不处罚；`/adforget`撤回主动学习，不自动解封。
- 纠正误封用`/adwrong AD-编号`或对应按钮，解封并撤回该案件样本。
- 普通解封用`/adunban AD-编号`，保留学习样本；同样广告可能再次命中。
- 学习不自动改写关键词、Prompt或程序，也不把全群聊天用于训练模型。

## 链接、机器人与照片边界

- 支持显式网址、Telegram text_link隐藏链接、配置的域名黑名单及机器人用户名疑似名单。
- 不自动打开任意网页或频道，不推断频道内广告；只发一个未知频道链接可能无法识别。未来链接抓取须独立实现超时、大小限制、私网地址防护和证据留存。
- @机器人及via_bot可以作为引流证据，但提及机器人不等于广告。不把广告机器人的后续内容直接归罪于某个提及它的成员；只处理实际收到的可归属消息。
- 照片视觉最多2MiB，选取适当尺寸；可识别清楚的广告文字、联系方式和二维码外观，未实现专用二维码解码器。
- 不支持视频、音频、贴纸画面、相册合并识别、历史消息扫描。

## 设置与权限

`/adsettings`或`/admanage`→检测设置：文字规则、照片视觉、行为、机器人引流、重复推广、AI分别切换。

- 设置按群生效；源群管理员或主人操作。私聊管理面板仅主人可打开。
- 设置按钮绑定原面板、目标群和24小时有效期，每次点击重新核查角色。
- 开关不改变处罚模式、域名黑名单、ID名单和管理员/白名单保护。
- 关闭文字规则不关闭AI文字理解；关闭照片不关闭照片说明文字检查。
- 设置改变后，旧开关下排队的AI结果不生成处罚案件。已存在的案件按模式、身份与截止规则处理；紧急暂停用`/admode observe`。
- 普通成员无法操作管理指令；可投票驳回，可私聊提交自己的误封申诉。
- 归档频道管理员可对原归档记录解封/纠错；不因此获得源群配置和处罚权限。
- 白名单只提供自动处罚豁免，不提供管理权限。有效封禁ID必须先解封，再加入白名单。

## 记录卡片与申诉

卡片显示`AD-编号`、来源群、群ID、成员ID、用户名、显示名、北京时间、判定来源、理由、截止时间和当前状态。归档还保存原证据消息、原文摘录、删除结果、封禁状态。ID和编号使用Telegram等宽实体；摘录点击揭开，原证据另行保留。

处罚记录提供“查看状态”“解除本群封禁”“判定误封并撤回学习”。只有真实处罚或结果不确定的封禁案件提供解除按钮；观察记录不伪装成已封禁。

被封成员私聊：`/adappeal AD-000001 申诉说明`。只允许本人、实际处罚案件，每案一次，最多300字。申诉写入原归档卡片与案件详情，由有权限管理员决定，不自动解封。机器人不会向陌生成员主动私聊，需成员先打开机器人。卡片更新失败时仍保留数据库申诉，可在案件详情查看。

## 检索与纠错

- `/adblacklist [页码]`：本群有效ID封禁名单。
- `/adhistory [用户ID] [页码]`：本群案件历史，可点归档链接。
- `/adwhitelist [页码]`：本群与全局白名单，明确显示范围。
- `/adaudit [页码]`：名单、设置、解封和纠错变更。
- `/adwhite add/remove 用户ID`：本群白名单。
- `/adgwhite add/remove 用户ID`：全局白名单，仅主人。

解封不等于自动重新入群，不恢复已删除内容。Telegram封禁可能清除成员历史消息。若出现较新封禁，旧案件不能解除新案件，须操作最新记录。

## 速度与资源

保留IPv4优先、TLS验证和IPv6备用。AI队列32、结果队列64、人工检查优先；自动排队90秒过期就跳过。模型请求20秒超时，失败不当成正常消息。

AI短期缓存128项、120秒TTL，仅内存；键包含群、模型、完整相关消息与功能开关。相同消息内容可复用，人工/adcheck绕过缓存；缓存只复用判断，不复用用户权限或执行结果。重启清空。重复证据最多500组、120秒，无全群原文持久化。

systemd原资源上限160MiB、CPU30%不增加；本版没有增加第三方Python依赖。实际端到端速度还受Telegram、模型供应商和群消息量影响，不能保证固定秒数。

## GitHub项目与交付

独立项目名建议`telegram-ad-killer`，优先私有仓库。上传源码、匿名测试、示例配置、部署模板、中文说明、方案、CI与MIT许可证。不上传真实config、Token、API Key、SQLite、日志、备份、成员数据、私有地址或实际运维审计。

执行顺序：核对当前版本→本地完整测试→脱敏检查→VPS暂存测试→停止服务并备份源码与数据库→原子替换→启动→校验模式、服务、权限、菜单与运行日志。出现启动失败恢复旧源码和停止期间的数据库快照。真实处罚不拿普通群友做生产测试。

## v1.0.1补充

AI失败、队列满、过期或不确定时，当前内容命中规则才创建无倒计时人工案件；不把AI故障当作无广告。消息编辑取消旧案件，新广告版本拥有独立编号和投票。满20张复核卡片后，最多200条额外案件保持held，仅通过面板/编号人工处理。

启用AI会将文本和照片传至配置的模型服务，需向成员说明。三票驳回只保证三个不同账号，不保证三个不同真人。留存、备份、容量及剩余边界见[审查修复说明](REVIEW-20261008.md)。

封禁完整成功后，群内bot复核通知保留180秒再自动删除；频道归档与案件元数据保留。删除任务持久化，重启后续办，每轮最多5条；权限/目标不存在等错误记录失败，其他错误有限重试。网络或队列拥堵可能延后执行。
